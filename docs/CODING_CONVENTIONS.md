# 코드 작성 기준

코드는 사람이 읽고 수정하는 원본입니다. 압축은 빌드 도구에 맡깁니다.

## 검사 명령

- `npm run format`: JS/JSX/MJS/CSS 포맷 통일
- `npm run format:check`: 같은 범위를 변경 없이 검사
- `npm run lint`: 미정의 이름·미사용 코드 등 정적 오류 검사
- `npm run check`: 공개 파일·포맷·린트·빌드·테스트 전체 실행

Prettier는 2칸 들여쓰기, 작은따옴표, 세미콜론, 100자 줄바꿈 기준입니다.
긴 문자열을 임의로 자르지 않습니다. 템플릿 HTML과 문자열 내부 문서는 출력 공백에
민감하므로 자동 포맷에서 제외합니다. 변경 시 직렬화와 PDF를 별도로 검증합니다.

## 이름과 배치

- 컴포넌트는 PascalCase, 훅은 use로 시작하는 camelCase입니다.
- 함수는 동작, 값은 의미를 설명하는 이름을 사용합니다.
- 컴포넌트 파일은 컴포넌트명.jsx, 일반 모듈은 kebab-case.js/mjs입니다.
- 여러 상태·실행문을 한 줄에 압축하지 않습니다. 중첩 분기와 긴 JSX는 책임을 설명하는 이름으로 분리합니다.
- import는 외부 패키지, 내부 모듈, 스타일 순서로 읽을 수 있게 둡니다.
- shared/utils에 코드부터 옮기지 않습니다. 실제로 함께 변경되는 책임을 먼저 찾습니다.

```js
// 피할 형태: const [open,setOpen]=useState(false),[error,setError]=useState('');
const [isOpen, setIsOpen] = useState(false);
const [errorMessage, setErrorMessage] = useState('');
```

## 상태·오류·주석

UI 상태, 편집 DOM, 저장 버전의 소유자와 갱신 경로를 구분합니다. 비동기 작업은 시작 시
문서 식별자, 완료 시 유효성 확인, 취소·정리 책임을 명확히 합니다. 오류는 처리 가능한
경계에서 사용자 메시지로 바꾸며 저장 실패를 성공으로 표시하지 않습니다. 의도적으로
복구하는 catch에는 이유를 설명합니다. 모듈의 복잡한 입력·출력은 JSDoc으로 기록하고
주석은 코드 번역 대신 이유·불변 조건·보안 경계를 설명합니다.

## 리뷰 기준

포맷 변경, 책임 이동, 기능 수정은 별도 커밋으로 검토합니다. 파일 길이만을 목적으로
쪼개지 않습니다. 수정 위치, 의존 방향, 상태 소유자가 명확한지 직접 확인합니다.
이름·설계 품질 전체가 린터로 강제되지는 않습니다. 가상 자료로 저장·복원·PDF·AI 충돌
보호를 검증하고 실제 실행 결과와 사람이 직접 확인한 내용을 구분해 기록합니다.
