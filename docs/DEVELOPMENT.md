# 개발 기록과 검토

이 저장소는 개인적으로 사용하는 도구의 구현과 검증 과정을 기록합니다. 실제 사용 문제는 이슈, 변경 이유와 확인 결과는 PR에 남깁니다. 외부 기여나 외부 승인자를 전제로 하지 않습니다.

## 작업 흐름

1. 버그 또는 작업·개선 이슈에서 사용 상황, 범위, 완료 조건을 정의합니다.
2. 의미 있는 대안을 비교하고 결정합니다. 지속적으로 영향을 주는 결정은 [설계 기록](decisions/0001-ai-proposal-conflicts.md)에 남깁니다.
3. 하나의 목적을 검토할 수 있는 크기로 구현하고 관련 테스트를 추가합니다.
4. PR에 변경 전후 결과와 테스트·코드 링크를 연결합니다. AI에게 맡긴 범위와 사람이 직접 확인한 범위는 구분합니다.
5. diff와 개인정보·라이선스 고지를 확인합니다. 검증하지 못한 환경과 남은 한계도 기록합니다.
6. 대표적인 문제 해결은 [사례](cases/ai-proposal-conflicts.md)로 정리합니다. 사소한 수정까지 별도 사례나 이슈를 만들지는 않습니다.

템플릿: [버그](../.github/ISSUE_TEMPLATE/bug.md), [작업·개선](../.github/ISSUE_TEMPLATE/task.md), [PR](../.github/PULL_REQUEST_TEMPLATE.md).
빈 이슈도 허용합니다. GitHub 템플릿 선택 화면에는 기본 브랜치 반영 후 나타납니다.

## 라벨

이슈·PR은 주목적 라벨 하나를 기본으로 합니다. 기능 구현에 테스트가 포함됐다고 test를 추가하지 않습니다.

| 라벨 | 기준 |
| --- | --- |
| feature | 새로운 사용자 기능 |
| enhancement | 기존 기능의 사용성·동작 개선 |
| bug | 의도한 동작과 다른 문제 |
| refactor | 사용자 동작을 유지하는 내부 구조 개선 |
| test | 테스트·검증 체계 개선 |
| docs | 문서 작성·수정 |
| chore | 개발 환경·의존성·빌드·CI 관리 |

기능 영역 라벨은 사용하지 않습니다. 기존 GitHub 기본 라벨은 이력 보존을 위해 자동 삭제하지 않습니다.

기준 데이터는 [.github/labels.json](../.github/labels.json)입니다. 저장소 쓰기 권한으로 로그인한 GitHub에서 위 이름·설명을 등록합니다. 기존 bug·enhancement는 재사용하며, documentation은 과거 이력 보존을 위해 그대로 두고 새 문서 작업은 docs로 분류합니다.

## 근거 기록 기준

- 구현 설명은 실제 코드, 테스트, 실행 결과로 연결합니다. 중요한 링크는 커밋이 확정되면 해당 커밋 기준으로 고정합니다.
- 개인 사용 경험을 다수 사용자의 성과로 확대하지 않습니다. 수치를 쓸 때는 전후 조건과 측정 방법을 함께 남깁니다.
- AI가 만든 부분과 외부 라이브러리를 자체 구현으로 표현하지 않습니다. AI의 설명만으로 테스트 통과를 기록하지 않습니다.
- 원문 대화나 프롬프트 전체를 공개하지 않아도 됩니다. 위임 범위, 채택·수정 판단, 검증 결과를 요약합니다.
- 과거 구현을 정리한 문서는 회고임을 밝힙니다. 당시 없었던 이슈·PR·리뷰·측정 결과를 만들어내지 않습니다.
- 실제 개인정보 대신 가상 입력을 사용합니다. PDF·영상·로그는 Git에 반복 누적하지 않고 재현 코드와 작은 결과 요약을 유지합니다.

## 자동 검사

[Check 워크플로](../.github/workflows/check.yml)는 main push, PR, 수동 실행에 대해 Ubuntu 24.04와 Node.js 22에서 npm run check를 실행하도록 구성했습니다.
최소 읽기 권한, 자격증명 비보존, 실행 제한 시간, 중복 실행 취소를 사용합니다. 실제 AI 계정과 비밀값은 필요하지 않으며 테스트 결과 파일을 자동 업로드하지 않습니다.

워크플로 파일의 존재와 원격 CI 통과는 별개입니다. 실행 결과는 해당 GitHub Actions 실행에서 확인하세요.
구성 기준은 [GitHub 보안 안내](https://docs.github.com/en/actions/reference/security/secure-use)를 참고했습니다.
