# 사용 가이드

## 기본 사용 흐름

1. 왼쪽에서 문서를 선택합니다. 템플릿은 첫 사용 시 개인 데이터 폴더에 복사됩니다.
2. 글을 클릭해 수정합니다. Enter는 새 문단, Shift + Enter는 줄바꿈입니다. 숫자 설정은 변경 후 Enter 또는 포커스 이동 시 적용됩니다.
3. 오른쪽 **바깥 박스 선택**으로 상위 박스를 고르고 크기·여백·색·순서를 조절합니다.
4. **구성 · 포함** 또는 **PDF에 포함** 체크로 출력 내용을 고릅니다. 제외는 삭제가 아닙니다.
5. 필요하면 상단에서 그래프와 다이어그램을 추가합니다. 삽입한 항목을 선택하면 다시 편집할 수 있습니다.
6. 약 1.2초 후 자동 저장됩니다. ⌘S로 즉시 저장, ⌘Z / ⌘⇧Z로 실행 취소/다시 실행합니다. Windows/Linux에서는 Ctrl을 사용합니다.
7. **PDF 내보내기**로 출력합니다. **원본에 반영**은 개인 데이터 폴더의 기준 HTML만 갱신하며, 저장소의 배포용 템플릿은 바꾸지 않습니다.

## 블록 모드와 레이아웃 모드

문서 제목 아래에서 전환합니다. 다른 파일로 변환하거나 사본을 만드는 작업이 아니라 **동일한 HTML을 보는 방식**입니다. 선택한 모드는 브라우저에 기억합니다.

| 블록 모드 | 레이아웃 모드 |
| --- | --- |
| 글과 블록 순서에 집중하는 1열 보기 | 실제 A4 지면과 박스·열 구성 보기 |
| 본문·제목·목록·인용문·구분선 추가 | 크기·정렬·색·여백·열 구성 조정 |
| 텍스트 형식 전환, 이동·복제·삭제 | 그래프·다이어그램 편집 |

블록 모드 조작:

- **＋ 블록 추가**로 빈 블록을 넣고 바로 입력합니다. 페이지·섹션을 선택했으면 그 안에, 텍스트를 선택했으면 그 뒤에 추가합니다.
- 텍스트를 클릭하고 **선택 블록 형식**에서 본문·제목·글머리/번호 목록·인용문으로 바꿉니다. 링크와 굵게 등의 인라인 내용은 유지합니다. 그래프·표·복합 컨테이너는 텍스트 블록으로 변환하지 않습니다.
- 빈 텍스트 블록에서 `/`로 형식 선택 메뉴를 엽니다. 목록에서 Enter는 다음 항목, 빈 목록 항목에서 Enter는 목록을 끝내고 본문으로 나옵니다. 일반 텍스트에서 Enter는 새 본문, Shift + Enter는 같은 블록의 줄바꿈입니다.
- 이동은 같은 상위 컨테이너 안에서 위·아래로 합니다. **블록 삭제**는 텍스트 또는 구분선에 적용되며 즉시 실행 취소할 수 있습니다. 출력에서만 빼고 싶다면 삭제 대신 **PDF에 포함**을 해제하세요.

블록 모드의 간소화된 크기·배치는 화면 전용 CSS입니다. 원래 HTML/CSS와 그래프 데이터는 유지하며 PDF는 항상 원래 지면으로 출력합니다. 텍스트를 길게 추가했다면 레이아웃 모드에서 A4 넘침 경고와 출력 결과를 확인하세요. 블록 보기에서 화면상 넘침 여부로 PDF 페이지 분량을 판단하지 않습니다. 원본의 복잡한 표·그래프는 전용 편집 창을 사용하세요. Notion/Figma의 모든 기능이나 자유 드래그 배치를 복제한 모드는 아닙니다.

**새 문서 → 문서 형식**에서 빈 A4, 블록형(소개·프로젝트·활동), 2열 문서를 선택합니다. 블록형 문서는 블록 모드로 열립니다. 어떤 형식이든 두 모드를 오갈 수 있으며 사본은 기존 디자인을 그대로 복제합니다.

## 선택 기능: Codex 채팅

이 기능을 사용하지 않아도 문서를 작성하고 출력할 수 있습니다.

1. 자신의 컴퓨터에 Codex CLI를 설치하고 터미널에서 `codex login`을 완료합니다.
2. 오른쪽 **Codex 채팅 → Codex 연결**에서 기존 로그인 상태와 모델을 조회합니다.
3. 모델·추론 강도와 **선택 블록 / 선택 페이지 / 문서 전체** 범위를 고릅니다.
4. 요청을 입력하고 전송 안내에 동의한 후 보냅니다. **질문만** 모드는 수정안을 만들지 않습니다.
5. **검토 후 적용 → 확인하고 적용**을 눌러야 문서가 변경됩니다. 응답 대기 중 직접 수정한 내용이 있으면 기존 제안의 적용을 막습니다.

**로컬 실행은 AI 추론까지 오프라인이라는 뜻이 아닙니다.** 요청문과 선택 HTML은 AI 제공자에 전송되며, 최근 대화 옵션을 켜면 해당 문서의 최근 메시지 최대 8개도 포함됩니다. 각자의 CLI 인증 방식에 따른 사용 한도 또는 요금이 적용됩니다. 이메일·비밀번호·토큰을 이 앱에 붙여 넣지 마세요.

기존 Codex 데스크톱 대화를 가져오는 기능이 아니라 편집기 전용 대화입니다. 문서 내용은 **연결**만 눌렀을 때 전송되지 않습니다. 문서별 대화는 로컬에 저장되며 AI는 원본 파일을 직접 쓰지 않습니다. 자세한 경계는 [보안·개인정보 문서](../SECURITY.md)를 참고하세요.

## 회사별 자료와 피드백

왼쪽 **회사별 자료**에서 회사명과 지원 직무를 등록하세요. 같은 회사라도 채용 포지션이나 지원 시기를 구분하고 싶다면 별도 항목으로 등록할 수 있습니다.

- **파일 선택 / 폴더 선택**: 한 회사에 사용할 파일을 고릅니다. 폴더 안의 `posting`, `resume`, `portfolio` 또는 공고·이력서·포폴이라는 이름으로 종류를 추정하므로, 보관 전에 드롭다운에서 확인하세요. 이름으로 구분하지 못하면 선택한 기본 자료 종류를 사용합니다.
- **선택 파일 보관**: 원래 파일을 옮기거나 수정하지 않고 복사합니다. 같은 회사·종류·파일명·내용의 성공적으로 읽은 자료는 중복 저장하지 않습니다. 같은 이름의 내용이 바뀌었다면 별도 사본이 됩니다.
- **채용 공고 붙여넣기**: 공고 본문과 선택적으로 출처 URL을 저장합니다. URL에 자동 접속하거나 공고를 갱신하지 않습니다.
- **현재 문서 보관**: 현재 편집 내용을 저장하고 회사별 HTML 사본으로 보관합니다. 이후 편집 내용은 자동으로 사본에 반영되지 않습니다. 필요할 때 다시 보관하세요.
- **내용 확인**: AI가 읽을 추출 텍스트를 확인합니다. 체크한 자료만 **냉정한 피드백** 버튼에 연결됩니다.

피드백 버튼은 공고 요건 대조, 우선 수정할 문제, 프로젝트 설명, 개인 기여와 팀 성과, 소개와 문장, 수정 예시와 면접 질문을 요청하는 프롬프트를 채팅에 준비합니다. 프롬프트를 직접 수정할 수 있으며 자동 전송하지 않습니다. 모델·추론 강도를 고르고 전송에 동의한 뒤 **보내기**를 눌러 주세요.

**선택 자료만** 범위는 질문 전용입니다. 체크한 자료의 추출 텍스트와 파일명·종류·회사명·직무·출처 URL을 보내며, 현재 편집 HTML은 포함하지 않습니다. 회사 자료를 보낼 때는 최근 대화 옵션이 기본으로 꺼집니다. 켜더라도 같은 회사·같은 자료 조합의 대화만 포함합니다. 답변은 현재 열려 있는 편집 문서의 로컬 채팅에 기록되며 회사명과 자료 조합이 함께 표시됩니다. 새로고침 후 회사 자료는 남지만, 전송할 자료는 다시 선택해야 합니다.

### 지원 형식과 제한

- 파일당 8MB, 한 번에 50개, 회사별 200개까지 보관합니다. 지원하지 않는 파일은 오류로 표시하고 가져오지 않습니다.
- TXT·Markdown·HTML은 UTF-8이어야 합니다. HTML은 실행하지 않고 텍스트를 추출하며 script/style/head와 `data-excluded="true"` 블록은 제외합니다. CSS로 숨긴 내용 등은 포함될 수 있으니 추출 결과를 확인하세요.
- PDF 추출에는 `pdftotext`가 필요합니다. macOS는 `brew install poppler`, Ubuntu는 `sudo apt-get install poppler-utils`로 설치할 수 있습니다. 미설치·암호·추출 실패·스캔 파일은 원본을 보관하되 경고하고 AI 선택에서 제외합니다. 설치나 파일 문제 해결 후 다시 가져오세요.
- 파일별 텍스트가 180,000자를 넘으면 AI 선택에서 제외합니다. 요청당 최대 12개·합계 240,000자입니다. 조용히 내용을 잘라 보내지 않습니다.
- PDF 이미지·시각적 배치와 HTML의 첨부 이미지·외부 리소스는 AI 입력에 포함하지 않습니다. 표의 순서는 추출 과정에서 달라질 수 있으니 내용 확인이 필요합니다.
- 가져온 자료는 참고용 사본입니다. 원본 폴더 감시·동기화나 PDF/HTML의 편집기 문서 변환은 하지 않습니다.

### 회사별 보관 구조

```text
applications/
└── <company-id>/
    ├── company.json            # 회사명·직무·자료 목록·원래 파일명
    ├── posting/                # 채용 공고
    ├── resume/                 # 이력서
    ├── portfolio/              # 포트폴리오
    └── other/                  # 기타 자료
```

자료 종류 폴더에는 `<material-id>.<원래 확장자>`와 `<material-id>.text.json`이 저장됩니다. 회사명·파일명이 같아도 덮어쓰지 않도록 내부 식별자를 사용합니다. 원래 파일명은 `company.json`과 화면에서 확인할 수 있습니다. 폴더와 파일을 직접 이름 변경하거나 다른 회사로 옮기면 연결이 깨질 수 있으므로 구조를 유지해 백업하세요.

## 저장소와 내 자료는 분리됩니다

| 운영체제 | 기본 개인 데이터 폴더 |
| --- | --- |
| macOS | `~/Library/Application Support/Career Studio` |
| Linux | `$XDG_DATA_HOME/career-studio`, 미설정 시 `~/.local/share/career-studio` |
| Windows | `%LOCALAPPDATA%\Career Studio` |

`STUDIO_DATA` 환경 변수로 다른 폴더를 지정할 수 있습니다. 개인 자료를 저장소 안에 두지 않는 것을 권장합니다.

| 개인 폴더 안의 경로 | 내용 |
| --- | --- |
| `originals/` | 사용자별 기준 HTML. 배포 템플릿 복사본과 새 문서 |
| `drafts/` | 최신 HTML, 최초 기준본, 변경 패치와 저장 버전 |
| `history/` | 기준 HTML에 반영할 때 기록하는 역복구 가능한 diff |
| `ai/chats/` | 요청·답변·수정안·적용 여부. 비공개 내용 포함 가능 |
| `exports/` | 문서별 최신 PDF |
| `custom.json` | 새 문서와 사본 목록 |
| `applications/` | 회사별 공고·지원 자료 원본 사본·추출 텍스트·메타데이터 |

백업하려면 서버를 종료한 뒤 **개인 데이터 폴더 전체**를 복사하세요. Git은 개인 데이터의 백업이 아닙니다. 새 버전의 템플릿이 배포되어도 기존 개인 기준본을 덮어쓰지 않습니다.

+## 회사별 편집 문서와 기본 양식
+
+**내 문서 → 회사 추가**에서 회사·직무를 만들고 **이 회사 문서 만들기**를 누릅니다. 새 문서 창의 **시작할 문서**에서 기본 양식이나 기존 문서를 선택하면 현재 저장된 내용을 독립적인 사본으로 복사합니다. 원래 문서는 바뀌지 않으며, 사본끼리 자동 동기화되지 않습니다.
+
+회사 정보는 **회사별 자료**와 공유합니다. 편집 문서는 왼쪽 회사 폴더에, 참고자료는 자료 창에 표시합니다. 편집 문서를 회사 폴더에 넣었다고 AI 참고자료로 자동 전송하지 않습니다. 피드백에 사용하려면 자료 창에서 현재 문서를 보관하고 직접 선택하세요.
+
+오른쪽 설정 아래 **회사 폴더**에서 사본의 회사를 바꾸거나 분류를 해제합니다. 문서 ID·HTML·수정 이력·PDF 경로는 그대로 두고 회사 연결만 바꿉니다. 다른 창에서 소속을 먼저 바꿨다면 충돌을 알립니다. 기본 양식 자체는 회사로 이동하지 않고 사본을 사용합니다.
+
+기본 양식은 이력서(문서·시각·PR 중심·요약), 포트폴리오(내러티브·상세·프로젝트 개요), 자기소개서(범용·문항·경험 중심), 통합 소개서로 구성됩니다. 작성 안내를 자신의 경험으로 바꾸고 불필요한 항목과 안내 문구는 제외하세요.
+
+## 박스와 내부 텍스트 선택
+
+레이아웃 모드에서 **박스 선택**을 켜면 제목을 눌러도 주변 박스를 선택합니다. **글자 편집**으로 돌아오면 문장을 직접 고칠 수 있습니다. 선택한 박스의 **박스 안 텍스트 선택** 목록에서 제목·본문·빈 텍스트 블록만 골라 수정하거나 삭제할 수도 있습니다.
+
