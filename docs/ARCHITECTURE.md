# 아키텍처와 설계 선택

## 범위와 책임

단일 사용자가 자신의 컴퓨터에서 실행하는 문서 편집기입니다. 웹 화면을 사용하지만 서버는 loopback 주소에만 바인딩합니다. 개인 데이터 저장과 AI 추론은 서로 다른 경계입니다.

| 구성요소 | 입력 | 책임 | 출력·저장 |
| --- | --- | --- | --- |
| React UI | 클릭·직접 입력·AI 요청 | 현재 문서·선택 범위·저장 상태 표시 | 로컬 HTTP 요청 |
| DocumentEditor | HTML·블록 조작 | iframe DOM 편집·직렬화·실행 취소 | HTML 문자열 |
| Node HTTP 서버 | 세션 토큰·문서 요청 | 문서 선택, 버전 검사, 저장·복구·출력 | 개인 데이터 폴더 |
| AIService | 선택 범위·사용자 요청 | 전송 동의, 수정안 검증, 기록, 승인·충돌 검사 | 질문 답변 또는 검토할 수정안 |
| CompanyStore | 회사 정보·선택 파일 | 종류별 보관, 원본 사본과 텍스트 추출, 회사별 참조 범위 검증 | applications 디렉터리 |
| CodexBridge | 제한된 프롬프트·모델 | App Server JSONL 프로토콜·중단·모델 조회 | 구조화된 응답 |
| Chromium | 저장된 HTML·로컬 리소스 | 인쇄 CSS 적용·출력 제외·이미지 확인 | 최신 PDF |

배포 템플릿은 읽기 전용 입력입니다. 처음 열 때 개인 `originals`로 복사하며, 이후 원본 반영은 이 복사본만 갱신합니다. 코드를 업데이트해도 사용자 자료를 덮어쓰지 않습니다.

## 문서 편집과 저장

1. 브라우저가 로컬 서버에서 문서 목록과 HTML을 읽습니다.
2. iframe은 스크립트가 실행되지 않는 상태로 문서를 표시합니다. 편집 엔진은 블록에 식별자를 부여하고 텍스트를 편집 가능하게 만듭니다.
3. 직렬화 때 선택 테두리, contenteditable, 임시 편집 CSS 등의 화면 전용 속성을 제거합니다. 블록 ID와 그래프 데이터는 유지합니다.
4. 자동 저장 요청에는 이전 저장 버전이 포함됩니다. 서버는 문서별 프로세스 내 큐에서 버전을 확인합니다.
5. 최신 HTML과 최초 기준본, 직전 내용과의 차이를 담은 패치를 기록합니다. 파일은 임시 파일 작성 후 rename으로 교체합니다.
6. 복원은 기준본에 지정 버전까지의 패치를 적용한 뒤 새 저장 버전으로 남깁니다.

HTML은 편집과 PDF의 공통 원문입니다. JSON 파일은 이를 저장하는 컨테이너이지 별도의 문서 레이아웃 언어가 아닙니다. 다이어그램만 재편집용 Excalidraw scene을 SVG와 함께 보관합니다.

## 편집 모드와 공통 원문

블록 모드는 별도 JSON이나 두 번째 contenteditable 문서가 아닙니다. 기존 iframe의 동일 DOM을 사용하며 `data-studio-mode`와 임시 CSS로 열·박스 배치를 읽기 쉬운 형태로 표시합니다. `serialize()`가 이 속성과 화면용 CSS를 제거하므로 저장·AI·PDF 경로는 원래 HTML을 받습니다. 모드 전환 자체는 변경 이력에 기록하지 않습니다.

`blocks.js`는 텍스트 블록 유형 전환, 목록 분리·본문 복귀, Enter로 블록 분할, 삽입·삭제를 처리합니다. DOM의 인라인 자식 노드를 이동하여 서식과 링크를 보존하고, 복사된 컨테이너의 식별자는 새로 생성합니다. 모든 문서 변경은 기존 checkpoint/changed 경로를 거치므로 실행 취소와 자동 저장을 공유합니다. 한글 조합 중 Enter와 `/`는 블록 명령으로 가로채지 않습니다.

`lib/new-document.mjs`는 허용된 새 문서 형식만 생성합니다. 블록형과 2열 모두 일반 HTML/CSS이며 사용자 데이터는 기존 저장소 밖의 originals/drafts 경로를 사용합니다.

## AI 요청과 적용

1. 전송 동의, 로그인 상태, 모델·추론 강도, 문서 버전을 확인합니다.
2. parse5의 원문 위치로 선택 블록·페이지를 잘라 냅니다. 전체 문서를 재직렬화해 관련 없는 내용을 바꾸지 않습니다.
3. 요청문과 선택 HTML, 사용자가 켠 경우 최근 대화 최대 8개를 전달합니다. 요청마다 일회성 Codex 작업을 사용합니다.
4. Codex는 `message`와 `edits[{before, after, reason}]` 형식의 응답을 반환합니다. 에이전트가 문서 파일을 직접 수정하는 방식이 아닙니다.
5. 각 before가 범위 안에서 정확히 한 번만 등장하는지, 치환이 겹치지 않는지, 금지된 리소스나 코드가 추가되지 않는지 검사합니다.
6. 사용자가 전후 비교를 검토하고 적용하면 문서의 최신 해시·버전을 다시 확인합니다. 요청 이후 직접 수정한 문서에는 이전 수정안을 적용하지 않습니다.
7. 승인된 수정은 기존 초안 저장 경로로 들어가고 실행 취소도 가능합니다. 원본 반영은 별도 동작입니다.

프롬프트의 지시만 보안 장치로 삼지 않습니다. 일회성 작업의 파일 읽기 제한·쓰기 금지·도구 제한, 호스트의 출력 검사, 사용자 승인, 문서 버전 검사를 함께 둡니다. 현재 검증은 보수적인 문자열·HTML 검사이며 범용 HTML 보안 제품을 대체하지 않습니다.

## 회사 자료와 평가 요청

브라우저 파일 선택기에서 명시적으로 고른 파일만 읽습니다. 서버에 임의의 로컬 경로를 전달해 폴더를 스캔하는 API는 없습니다. 파일명은 표시용이며 저장 경로는 서버가 생성한 회사·자료 ID와 허용된 종류로 구성합니다. 회사별 큐 안에서 원본 사본, 추출 텍스트, 목록을 저장합니다. 각 파일은 원자적으로 교체하지만 전체 작업의 트랜잭션이나 자동 동기화는 아닙니다.

HTML은 parse5로 텍스트만 추출하고, PDF는 셸 없이 `pdftotext`를 제한 시간·출력 크기와 함께 실행합니다. 추출 결과가 없거나 제한을 넘으면 명시적으로 경고하고 AI 선택을 차단합니다. 원본 파일은 정적 웹 경로로 제공하지 않습니다.

회사 자료 요청은 `scope=materials`, `mode=ask` 조합만 허용합니다. 서버가 회사 ID와 선택한 자료 ID의 소속을 확인하고 텍스트를 로드합니다. 현재 편집 HTML은 빈 문자열로 전달하고, 모델이 수정안을 반환해도 폐기합니다. 최근 대화는 회사 ID와 선택 자료 ID·해시 조합으로 구분하여 다른 회사나 미선택 자료에 관한 대화가 섞이지 않도록 합니다. 프리셋 클릭과 실제 전송은 분리되며, 새 자료를 연결하면 전송 동의를 해제합니다.

## PDF 출력

출력 요청은 최신 저장 버전을 확인합니다. 짧은 수명의 render URL로 Chromium에 HTML을 제공하고, 외부 네트워크 요청을 차단합니다. 체크 해제한 요소는 출력 DOM에서 제거하고 마지막 페이지의 강제 페이지 나눔을 정리합니다. 글꼴 준비와 이미지 로드를 확인한 후 PDF를 생성합니다.

PDF는 파생 결과물입니다. 수정 이력을 여러 PDF 파일로 쌓지 않고 문서별 최신 PDF만 유지합니다. 원문과 패치는 개인 데이터 폴더에 남습니다.

## 선택한 이유와 비용

| 선택 | 얻는 점 | 한계·비용 |
| --- | --- | --- |
| HTML/CSS를 원문으로 유지 | 사람이 읽고 AI가 작은 범위를 고치기 쉬움 | 임의 HTML 전체를 완벽하게 지원하기 어려움 |
| 파일·패치 기반 저장 | 별도 DB 설치 없이 복구 가능한 로컬 작업 | 대규모 이력·검색·다중 프로세스 동시성에 한계 |
| 명시적 수정안 승인 | AI 결과와 실제 반영을 분리 | 한 단계 더 검토해야 함 |
| 변경 시 수정안 적용 차단 | 직접 입력 내용 보존 | 무관한 작은 수정도 다시 요청해야 할 수 있음 |
| 로컬 서버 + 외부 AI | 개인 파일 호스팅 서버가 필요 없음 | AI 요청에는 네트워크·계정 필요 |
| Chromium 인쇄 | HTML 미리보기와 같은 렌더링 계열 | 글꼴·운영체제 차이와 출력 프로세스 비용 |

## 운영 및 데이터 일관성

- 문서별 큐는 단일 Node 프로세스 안에서만 유효합니다. 같은 데이터 폴더를 여러 서버에서 동시에 열지 마세요.
- 원본 HTML과 Markdown 반영 기록은 별개 파일입니다. 각 파일의 교체는 원자적이지만 두 파일 전체에 걸친 DB 트랜잭션은 아닙니다.
- 작업 상태는 서버 메모리에, 완료된 대화는 파일에 있습니다. 서버 재시작 시 진행 중이던 AI 작업을 자동 재개하지 않습니다.
- 대화·HTML·출력은 로컬 평문입니다. 기기 로그인·디스크 암호화·백업 관리는 사용자 책임입니다.

## 회사 폴더와 선택 안전장치

회사별 편집 문서는 별도 디렉터리로 복제하지 않고 외부 `custom.json`의 선택적 `companyId`로 분류합니다. CompanyStore의 회사 정보를 검증하며, 회사 변경 API는 catalog 큐 안에서 `expectedCompanyId`를 비교합니다. 폴더 변경은 문서 버전이나 HTML 패치를 생성하지 않습니다. 참고자료와 편집 문서는 회사만 공유하고 저장·AI 전송 경계는 별도로 유지합니다.

선택 모드는 편집기의 일시적 상태입니다. 박스 선택 중에는 직접 입력과 붙여넣기를 막으며 블록 모드로 전환하면 글자 편집으로 돌아갑니다. 삭제 확인 시 실제 DOM 노드의 연결 상태·소속 문서·현재 선택 일치를 재검사합니다. 마지막 페이지, 루트 영역, 그래프 내부 관리 노드를 보호하고 변경은 기존 undo/save 경로를 사용합니다.
