# AI 요청 이후의 직접 편집을 보호하기

이 문서는 기존 구현과 테스트를 2026-09-15에 읽고 사후 정리한 사례입니다. 실제 사용자 데이터 손실 사고를 보고하는 글이 아닙니다.

## 문제와 목표

AI 수정안을 받은 뒤 사용자가 직접 고친 문서를 이전 제안으로 덮어쓰지 않아야 합니다.
단순한 응답 생성뿐 아니라 승인 전 원문 유지, 승인 후 적용, 충돌 시 거절을 확인해야 합니다.

## 구현과 판단

[AIService](../../ai-service.mjs)는 제안의 기준 HTML 해시를 저장하고, decide에서 문서 잠금 안에서 최신 해시·revision을 비교합니다.
비교 실패 시 저장하지 않고 오류를 반환합니다. [AIChat](../../src/AIChat.jsx)은 수정 전후 비교와 명시적 적용 단계를 제공합니다.
자동 병합 대신 보수적 거절을 사용하는 이유와 비용은 [설계 기록](../decisions/0001-ai-proposal-conflicts.md)에 정리했습니다.

## 재현 절차

```sh
npm run build
npm run test:ai
```

1. 테스트가 임시 저장소와 가짜 AI 서버로 가상 문서를 만듭니다.
2. 제목 변경을 요청한 후 승인 전 제목이 그대로인지 확인합니다.
3. 승인하면 수정되고 undo/redo가 가능한지 확인합니다.
4. 다음 제안을 받은 뒤 제목을 직접 고칩니다.
5. 이전 제안을 적용하면 변경 오류가 표시되고 직접 고친 제목이 유지되는지 확인합니다.

[단위 테스트](../../test/ai.test.mjs)는 서버 측 거절과 원문 보존을, [UI 테스트](../../test/ai-ui.mjs)는 실제 브라우저 승인·오류 표시 흐름을 검사합니다.

## 결과 해석과 한계

통과 결과는 위 가상 시나리오에서 직접 입력을 보존한다는 근거입니다. 모든 동시성 문제 해결, 데이터 손실 0건, 실제 AI 품질 향상을 뜻하지 않습니다.
선택 범위 밖 수정도 전체 해시를 바꾸므로 다시 요청해야 할 수 있습니다. 사용 시간 절감이나 실사용 충돌 빈도는 측정하지 않았습니다.

## 작성과 AI 활용 범위

이번 사례 문서와 운영 설정은 사용자 승인 범위를 바탕으로 코딩 에이전트가 기존 코드·테스트를 읽고 작성했습니다. 사용자가 이번 테스트를 직접 수행한 것으로 기록하지 않습니다.
기존 구현의 세부 작업 분담이나 당시 대안 비교는 이 문서만으로 확인할 수 없어 소급해 주장하지 않습니다.
실행 환경과 검사 범위는 [검증 안내](../VALIDATION.md)를 참고하세요.
