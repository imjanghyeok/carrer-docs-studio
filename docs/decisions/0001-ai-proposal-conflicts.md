# 0001. AI 수정안은 검토 후 적용하고 문서가 달라지면 차단한다

- 기록일: 2026-09-15
- 상태: 현재 구현을 사후 정리한 설계 기록
- 범위: 단일 로컬 서버의 문서 수정안 적용

## 상황과 제약

AI 응답을 기다리는 동안 사용자는 문서를 직접 편집할 수 있습니다. 이전 문서에서 만들어진 수정안을 그대로 반영하면 새 입력과 충돌할 수 있습니다. 요청과 적용 사이에 사용자 검토가 있고 HTML 원문을 유지해야 합니다.

## 현재 선택

[AIService.request / decide](../../ai-service.mjs)는 요청 시 문서 해시를 기록하고 적용 시 현재 HTML 해시와 비교합니다. 적용 요청의 revision도 현재 저장 revision과 비교합니다. 검사는 문서 잠금 안에서 이루어지며 충돌하면 409 오류로 거절합니다.
수정안 자체도 선택 범위, 치환 중복·겹침, 위험한 리소스 추가 여부를 검사합니다.

## 대안과 비용

다음 비교는 현 구현을 설명하기 위한 사후 분석이며, 당시 실제 검토 회의나 성능 실험 기록이 아닙니다.

| 방식 | 이점 | 비용 |
| --- | --- | --- |
| 바로 반영 | 조작 단계가 적음 | 사용자 검토 없이 변경됨 |
| 변경 구간 자동 병합 | 무관한 편집과 공존 가능 | 충돌 판단·HTML 구조 보존이 복잡해짐 |
| 검토 후 해시·버전 확인 | 적용 경계가 명확하고 재현 가능 | 무관한 수정도 재요청이 필요할 수 있음 |

## 한계와 재검토 조건

해시는 문서 전체를 비교합니다. 자동 병합이 아니며 문서가 같은 내용으로 돌아왔을 때의 의미적 충돌을 판별하지 않습니다. 잠금은 단일 프로세스에 한정됩니다.
무관한 편집 때문에 재요청하는 사례가 실제 사용에서 반복되면 범위별 병합을 검토할 수 있습니다. 현재 그런 빈도나 비용은 측정하지 않았습니다.
